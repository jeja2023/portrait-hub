# 影鉴 0.18.0 发布说明

- 发布日期：2026-07-26
- 发布类型：商业产品能力功能版本
- API 兼容性：继续使用 `/v1`；对比 0.17.0 OpenAPI 基线新增能力，无破坏性路径或契约变更
- 数据兼容性：新增商业控制面、计量、反馈、模型注册、Webhook 投递和视频续传状态；生产部署必须先备份并执行幂等迁移
- SDK 支持：Python 稳定支持，Node 维护支持，Go/Java 实验性参考实现
- 发布结论：仓库计划与自动化验证已完成；真实模型、目标基础设施演练、法律/产品审批和生产观察未完成，完整生产发布门禁继续阻塞

## 版本摘要

0.18.0 将 0.17.0 的多项目结构化解析平台扩展为具备商业运营、使用治理、模型治理、反馈闭环和标准化交付能力的产品基线。商业客户从试用到关闭的状态、授权和并发限制可以审计并回滚；每次资源使用可以幂等计量、冲正、归集成本和预测配额；模型从来源、评估、审批到灰度、热更新和回滚具有可验证证据；反馈、标注、数据集和候选模型决策形成受控闭环。

本版本同时交付可恢复视频、Webhook 投递治理、近期认证、合规证据、Kubernetes 稳定/灰度发布物、支持矩阵、API 兼容检查、Python SDK 产品化和商业运营控制台。所有仓库内计划项均有实现或门禁；仓库无法替代的真实模型、GPU 容量、目标集群演练、法律适用性和人工审批被明确保留为外部阻塞项。

## 商业客户与授权

### 客户生命周期

- 客户状态覆盖 `trial`、`active`、`grace`、`suspended`、`offboarding` 和 `closed`。
- 状态变更支持立即执行或未来定时激活，允许在激活前取消，并记录原因、操作者、审批人和前后版本。
- 写入使用 revision/CAS；并发修改不会静默覆盖。已生效变更保留可审计回滚目标。
- 关闭必须与数据权利处理和删除证据关联，不能只改变展示状态。

### 授权和许可证

- 授权版本支持续约、升级、降级、临时扩容、紧急授权、激活区间、自动恢复和指定版本回滚。
- 并发额度和分配上限通过共享 Redis 状态实施，多副本下保持一致。
- 离线环境可以使用 Ed25519 签名许可证；服务端验证签名、期限、客户和授权内容，拒绝篡改或过期许可。
- 支持工单、客户退出和删除后关闭流程进入统一商业控制面。

## 不可变计量与成本治理

- 原始用量事件不可更新或删除；相同幂等键只接受完全一致的载荷，冲突载荷返回稳定错误。
- 任何调账都创建关联原事件的冲正事件，保留净额、原因和审计链。
- 维度覆盖租户、项目、应用、模型、能力、端点和资源；指标覆盖图片、视频、GPU、存储、网络和第三方使用量。
- 结果分类区分成功、业务拒绝、系统失败、重试和重复，避免把重试流量或业务拒绝误计为成功消费。
- 按客户时区提供日/月聚合，成本模型按有效时间版本化；预算状态、配额余额和耗尽时间预测使用同一不可变事件源。
- SLA 报告、事件和支持工单采用版本化记录，服务质量页面展示成功率、延迟、预算、配额和事件状态。

## 模型调度、注册与发布

- 推理调度支持动态批处理、租户公平、排队超时、主动取消和受控降级。
- 模型注册中心记录制品来源、SHA256、评估、审批、发布状态、别名和回滚关系。
- 热更新只接受可信制品，先校验指纹并预热，再使用别名 CAS 原子切换；同一请求不会混合新旧版本。
- 影子推理异步记录候选输出和比较证据，不改变主链路响应。
- 五套行业模板具备不可变版本、预览、指纹、应用历史和回滚；模板清单与真实仓库 spec SHA 绑定，缺少证据时关闭失败。

## 反馈与数据闭环

- 反馈样本池保存来源、治理状态、脱敏、去重和优先级信息。
- 标注导出/导入具有稳定清单、冲突处理和数据集血缘，不覆盖已有人工结论。
- 分析结果不可变，覆盖错误分布、只读阈值建议、基线/候选指标和发布 `recommend`/`hold` 决策。
- 发布决策校验数据集 manifest 和模型 SHA256，防止使用未审计数据或错配制品。
- COM-006 权限控制贯穿反馈导出、数据权利导出和管理员导出。

## 视频与 Webhook

- 视频使用分片、偏移和检查点实现可恢复上传；任务支持优先级、取消、重试、故障恢复和结果轮询。
- 流式任务设置连续失败重连预算，避免每次短暂成功无限重置总体失败风险。
- 回调时间线记录任务和投递状态，便于定位上传、执行和通知的边界。
- Webhook 保存签名、每次投递尝试、重试计划、响应摘要和最终状态；失败进入死信，可按项目隔离查看和人工重投。

## 安全、隐私与合规

- 删除、导出、发布、回滚、密钥轮换和商业/合规关键操作要求近期交互认证。
- 本地账号通过密码重输完成 step-up；OIDC 强制 `prompt=login`、`max_age=0` 并校验 NumericDate `auth_time`。API Key、平台令牌和非交互式服务 JWT 不具备 step-up 资格。
- COM-001 至 COM-012 使用控制项专属语义校验，不以一份通用附件伪装全部控制完成。
- 数据权利工作流记录六类后端的删除证据；证据包使用 Ed25519 签名并串联隐私、安全和需求追踪记录。
- 法律适用性、影响评估和控制审批仍需责任人真实签署；工具不会生成虚假审批记录。

## Console Next

- 新增商业运营、服务质量、合规、模型注册和 Webhook 投递调试页面。
- 页面覆盖客户状态与授权版本、计量/成本、预算与配额预测、支持工单、模型审批/发布/回滚、合规控制和证据查看。
- 列表统一提供加载、空数据、错误、分页和跨页连续序号；高风险操作显示资源与影响并触发二次确认和近期认证。
- 已在 Chromium 桌面/平板/移动端、Firefox 桌面和 WebKit 桌面执行真实浏览器流程。

## Kubernetes 与发布工程

- 基础发布物包含 API、worker、服务、配置、密钥引用、网络/安全策略、PDB、HPA/KEDA、GPU 亲和和迁移 Job。
- 发布物化要求稳定版和灰度版使用不同不可变 SHA256 镜像、真实 FQDN 和完整依赖配置；校验器覆盖 27 个资源。
- 新增 `portrait_postgres_migrate.py`、`portrait_release_preflight.py`、`portrait_kubernetes_release.py`、`openapi_compatibility_check.py`、`portrait_support_matrix.py`、`portrait_sdk_clean_smoke.py`、`portrait_evidence_package.py` 和 `portrait_upgrade_traceability.py`。
- 当前 OpenAPI 有 154 条路径，0.17.0 基线为 147 条，检查结果为 0 个破坏性变更。

## 升级步骤

1. 进入维护窗口，暂停商业状态、授权、模型别名、反馈导入、Webhook 配置和模板应用写入。
2. 备份 PostgreSQL、Redis、对象存储、运行状态、`.env`、模型制品和当前稳定/灰度镜像摘要。
3. 拉取 0.18.0 并确认版本：

```bash
git fetch origin
git pull --ff-only origin main
grep -F 'version = "0.18.0"' pyproject.toml
```

4. 检查支持矩阵和 API 兼容性：

```bash
python tools/portrait_support_matrix.py --json
python tools/openapi_compatibility_check.py
```

5. 对目标 PostgreSQL 运行幂等迁移并执行发布前检查：

```bash
python tools/portrait_postgres_migrate.py --dsn "$POSTGRES_DSN" --apply
python tools/portrait_release_preflight.py --check-migrations
```

6. 重新构建并发布 API、worker 和 Console Next；Kubernetes 环境使用不同的稳定/灰度 SHA256 镜像物化清单。
7. 验证客户生命周期、授权、计量、成本、模型、反馈、视频续传、Webhook 重投、近期认证和跨项目隔离。
8. 执行平台门禁、SDK 干净环境烟测、目标环境容量与故障恢复演练；只有完整严格门禁和外部审批全部通过后才能切换生产流量。

详细命令和环境要求见 [Ubuntu 部署指南](../deployment/DEPLOY_UBUNTU.md)、[Kubernetes 发布指南](../deployment/KUBERNETES_RELEASE.md)、[商业数据迁移](../deployment/COMMERCIAL_DATA_MIGRATION.md) 和 [商业发布门禁](../operations/COMMERCIAL_RELEASE_GATE.md)。

## 回退边界

- 回退应用前先停止 0.18.0 写流量并导出升级后商业事件、授权版本、模型别名、反馈清单和 Webhook 投递记录。
- 数据库迁移遵循 expand-first；回滚窗口内保留新增表、索引和字段，不执行破坏性删表。
- 0.17.0 不理解新增商业控制面和事件语义。只要 0.18.0 已产生商业状态、计量、反馈或模型发布数据，就不能让 0.17.0 对这些域恢复写入。
- 可将 API/Console/worker 镜像回退到已验证摘要用于只读排障；需要恢复写流量时，应重新部署 0.18.0，或由变更负责人明确接受数据丢失后恢复升级前完整快照。
- 模型别名回退使用注册中心的受控回滚记录；不要手工修改运行配置以绕过指纹、预热或 CAS。

因此，0.18.0 是完成仓库计划的商业能力发布基线，不代表上述外部生产验收已经完成。以 [商业升级状态](../plans/COMMERCIAL_PRODUCT_UPGRADE_STATUS.md) 和机器可读需求卡的当前状态作为最终发布决策依据。
