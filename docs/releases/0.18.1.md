# 影鉴 0.18.1 发布说明

- 发布日期：2026-07-27
- 发布类型：性能、配置健壮性与交付可靠性补丁版本
- API 兼容性：继续使用 `/v1`；公开路径、请求/响应契约和 OpenAPI 基线无破坏性变更
- 数据兼容性：数据库 schema 不变，不需要数据迁移
- SDK 支持：Python 稳定支持，Node 维护支持，Go/Java 实验性参考实现
- 发布结论：仓库内优化和自动化验证已完成；真实模型、目标环境容量/故障演练与人工审批状态不变

## 版本摘要

0.18.1 在 0.18.0 商业产品能力基线上收敛控制面写放大、锁竞争、阻塞 IO 资源争用、配置拼写错误静默回退和交付网络耦合。补丁不新增公开业务能力，不改变 `/v1` 契约，也不执行破坏性数据库迁移。

控制面实体投影现按内容变化增量写入，快照读取移到共享锁外；文件与数据库持久化使用独立 IO 线程池。类型化配置会告警并在生产启动时拒绝非法值。Docker 默认使用官方软件源并允许构建参数覆盖，主 CI 按职责并行执行且只在主流水线安装 Chromium。

## 控制面性能与一致性

- `_sync_control_entities` 使用 `ON CONFLICT ... DO UPDATE ... WHERE (...) IS DISTINCT FROM (...)`，重复保存未变化实体时不产生行更新。
- 快照实体消失后，通过并行 `unnest` anti-join 清理对应投影；空快照会清理该状态域的全部实体投影。
- `ControlStateBackend.operation()` 在获取全局 `RLock` 前读取 PostgreSQL 快照，锁内只应用更新的 revision。
- revision CAS、409 冲突、刷新和调用方重试语义保持不变；新增回归验证冲突后重试成功。
- 本版本不实施 `(state_key, tenant_id)` 分片。该项需要双写、回填、校验和回滚路径，按优化计划 M1 独立迁移。

## 阻塞 IO 隔离

- `run_blocking_io` 使用进程内 `portrait-io` 专用 `ThreadPoolExecutor`，避免状态落盘、审计写入和控制面持久化占满推理/媒体解码使用的默认池。
- `BLOCKING_IO_THREAD_POOL_SIZE` 默认按 CPU 数量计算并限制上界；`.env.example` 提供 `32` 的部署样例。
- lifespan 停机顺序先完成状态和统计刷新，再关闭专用线程池，避免停机阶段丢失已提交任务。

## 配置健壮性与诊断

- 整数、浮点和布尔环境变量解析失败时记录一次 warning，并汇总变量名和期望类型。
- 布尔配置只接受 `1/0`、`true/false`、`yes/no`、`on/off`；浮点配置拒绝 `NaN` 和无穷值。
- 开发环境继续使用默认值以便诊断；生产 profile 的启动门禁汇总非法配置并 fail-fast，即使关闭外部服务强制门禁也不能绕过。
- warning 不包含原始环境值，避免配置或凭据内容进入日志。
- 动态 GPU 设备发现失败时记录异常类型，然后使用既有配置设备或设备 `0` 回退。

## Docker 与 CI

- GPU 镜像新增可选 `APT_MIRROR`；留空时沿用 Ubuntu 基础镜像官方源。
- GPU 和 CPU 镜像新增 `PIP_INDEX_URL`，默认 `https://pypi.org/simple`。国内、代理或隔离环境可以在构建时显式传入镜像地址。
- GitHub Actions 主 CI 拆为 `lint-type`、`python-tests`、`frontend-e2e`、`delivery-gates` 四个无依赖 job。
- `~/.cache/ms-playwright` 使用锁文件摘要缓存；主 CI 安装 Chromium 并运行 desktop/tablet/mobile 项目，本地完整 Firefox/WebKit 项目不变。
- 部署门禁检查软件源参数化、官方默认值、四 job 并行结构、Chromium 缓存和浏览器安装范围。

## 升级步骤

1. 记录当前提交、镜像摘要和 `.env` 备份；本补丁不要求停止业务写入或执行数据库迁移。
2. 拉取代码并确认版本：

```bash
git fetch origin
git pull --ff-only origin main
grep -F 'version = "0.18.1"' pyproject.toml
```

3. 检查现有环境变量。生产配置中的非法整数、浮点或布尔值将不再静默回退，必须先修正。
4. 按网络环境构建镜像。默认官方源；需要镜像时可传入：

```bash
docker compose -p portrait-hub build --pull \
  --build-arg APT_MIRROR=https://mirrors.tuna.tsinghua.edu.cn/ubuntu \
  --build-arg PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple
```

5. 滚动重建 API 和 worker，验证 `/health`、`/ready`、控制面读写、GPU 清单和审计写入。
6. 执行平台门禁：

```bash
python tools/portrait_support_matrix.py --json
python tools/openapi_compatibility_check.py
python tools/portrait_production_readiness.py --scope platform --strict
```

## 回退边界

- 0.18.1 没有数据库 schema 或数据格式迁移，可以直接回退到已归档的 0.18.0 应用和前端镜像。
- 回退前仍应停止新流量并确认没有正在执行的控制面写入或视频任务，以避免进程切换造成请求中断。
- 0.18.0 会重新允许非法类型配置静默回退，且恢复原有线程池、控制面锁和写入行为；回退后应继续保留已修正的配置值。
- 不要只回退 Console Next 的 `index.html`；HTML、manifest 和哈希静态资源必须来自同一次构建。
