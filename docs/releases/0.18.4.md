# 影鉴 0.18.4 发布说明

- 发布日期：2026-07-29
- 发布类型：依赖安全、Docker/GPU 联调与媒体兼容修复补丁
- API 兼容性：继续使用 `/v1`；公开路由、请求响应契约和 OpenAPI 基线不变
- 数据兼容性：数据库 schema、持久化格式和迁移策略不变，不需要数据迁移

## 版本摘要

0.18.4 清理根 npm workspace 中 8 个开发工具链高危项，将 Node.js 构建基线升级到 22.22.2，并通过精确依赖、npm overrides 和幂等的 Redocly `js-yaml` 兼容补丁保持 OpenAPI 生成与干净 Docker 构建可用。Windows Python 环境增加 `tzdata 2026.3` 精确锁定，避免本地时区数据缺失。

本版本同时完成本地 Docker、PostgreSQL、Redis、ArangoDB 和 NVIDIA GPU 联调。模型配置写入兼容只读父目录中的可写 bind mount 文件，修复控制台修改模型 GPU 设备时的 500。图片推理响应会返回归档后的公开缩略图；离线视频上限提升到 1 GiB，MP4 校验支持合法 ISO-BMFF 前置 box，前端不再依赖浏览器 MIME 映射，并将上传超时提高到 30 分钟。

配置中心为原先缺失说明的 62 项配置补齐逐项中文文档，并记录可配置 GPU Bridge 网络，当前 240 项配置说明完整率为 100%。这些说明仍以 `.env.example` 为单一来源，控制台和部署模板不会产生两套互相漂移的描述。

## 主要变更

### 依赖与构建

- Node.js builder、根 workspace 和 Console engines 统一为 `>=22.22.2 <23`。
- `@vue/test-utils`、`openapi-typescript`、`js-beautify`、`js-yaml` 和 `minimatch` 使用经过审计的精确版本或 overrides。
- `tools/patch_openapi_core.js` 由 npm `postinstall` 幂等执行，GPU/CPU Dockerfile 的干净 `npm ci` 同样应用该补丁。
- Windows Python 依赖清单和锁文件增加 `tzdata==2026.3`，部署门禁验证所有 GPU/CPU 清单一致。

### Docker 与 GPU

- `write_raw_model_config` 在无法创建同目录临时文件时回退为直接覆盖目标 bind mount 文件，保留其他场景的原子替换路径。
- Compose 的 GPU Bridge 网络支持通过 `GPU_BRIDGE_NETWORK` 指定已有网络名。
- 本地 RTX 3070 Laptop GPU 验证 YOLOv8 和 OSNet 均使用 `CUDAExecutionProvider`、`device_id=0`；离线视频由独立 `portrait-video-job-worker` 消费完成。

### 图片与视频

- 图片推理响应使用公开归档 payload，立即返回可显示的 JPEG Data URL 缩略图；归档数据库不保存 Base64 图片正文。
- `MAX_VIDEO_BYTES` 默认值调整为 `1073741824`，`MAX_REQUEST_BODY_BYTES` 调整为 `1090519040`，为 1 GiB 文件预留 16 MiB multipart 开销。
- ISO-BMFF 探测解析前 64 KiB 顶层 box，支持 `free`、`ftyp`、`styp`、`moov`、`mdat`、`moof` 和 64 位 box 长度。
- Console Next 支持 MP4、MOV、M4V、AVI、MKV、WebM 扩展名，前端执行 1 GiB 上限检查，上传超时为 30 分钟。

### 配置说明

- 补齐图库并发、默认模型、视频分片、模型排空、动态批处理、商业授权、Webhook、本地登录、OIDC/JWT、控制台票据、存储加密、OpenTelemetry、PostgreSQL 和任务队列等 62 项说明。
- 配置目录回归测试要求所有配置说明均为非空，并抽查本地管理员配置说明。

## 升级步骤

1. 备份 `.env`、`runtime-state`、模型配置、模型目录和当前镜像清单。
2. 拉取 `0.18.4` 代码并确认版本：

```bash
git fetch origin
git pull --ff-only origin main
grep -F 'version = "0.18.4"' pyproject.toml
```

3. 运行依赖安装和发布前检查：

```bash
python -m pip install -r requirements.txt
npm ci
python -m pytest -q tests/test_release_version.py tests/test_support_matrix.py tests/test_deploy_check.py
npm run console:check
```

4. 使用新的 Dockerfile 重建 API 和视频 worker 镜像，重新创建相关容器。生产部署应保持 `MAX_REQUEST_BODY_BYTES` 比 `MAX_VIDEO_BYTES` 多 1 至 16 MiB。
5. 验证 `/health`、`/ready`、控制台本地/OIDC 登录、模型 GPU 设备修改、图片预览、MP4 上传和独立视频 worker。

## 回退

0.18.4 不包含数据库迁移，可以回退到完整归档的 0.18.3 应用和前端镜像。回退时必须成套恢复 API/worker 镜像、Console 静态资源和对应依赖锁；若继续保留 1 GiB 上传能力，不得把请求体上限单独回退到 112 MiB。回退模型配置文件前先备份运行期 `models.yml`，避免覆盖控制台已经保存的设备设置。
