# 影鉴 0.18.3 发布说明

- 发布日期：2026-07-27
- 发布类型：CI 构建与供应链扫描修复补丁
- API 兼容性：继续使用 `/v1`；公开路由、请求响应契约和 OpenAPI 基线不变
- 数据兼容性：数据库 schema、持久化格式和迁移策略不变，不需要数据迁移

## 版本摘要

0.18.3 修复 0.18.2 发布后暴露的容器交付问题。GPU/CPU Dockerfile 不再复制被 `.dockerignore` 排除的 `tools/`，因此运行时镜像可以正确进入依赖安装和安全扫描阶段。Trivy 与 Scorecard 的 SARIF 上传仅在结果文件生成时执行，保留扫描或构建步骤的原始失败状态，不再产生误导性的缺失文件二次错误。

同时，GitHub Actions 官方运行时统一升级到当前主版本：`checkout@v7`、`setup-python@v7`、`setup-node@v7`、`cache@v5`、`upload-artifact@v7`、`download-artifact@v8` 和 `codeql-action/upload-sarif@v4`。部署门禁新增 Docker 构建上下文、SARIF 文件保护和 Action 版本契约测试。

远端首次回归确认 CPU 镜像、GPU 运行时镜像、运行时烟测、SBOM 和 SARIF 上传已恢复，随后继续收口干净检出差异：Python 测试与交付门禁会先构建 Console 静态产物；模型注册测试使用隔离小构件；Playwright 对共享服务和运行时状态使用单 worker，并通过专用 CI 命令固定 Chromium 桌面、平板、移动端三个项目。Trivy 继续阻断已有修复方案的高危/严重漏洞，只忽略上游暂未提供修复版本的条目。

## 升级与回退

1. 备份当前 Compose 配置、模型目录、运行状态和镜像清单。
2. 拉取代码并确认所有运行时、Console Next 和 SDK 版本为 `0.18.3`：

```bash
git fetch origin
git pull --ff-only origin main
grep -F 'version = "0.18.3"' pyproject.toml
```

3. 重新构建目标镜像；GPU、CPU 编排分别使用 `Dockerfile` 和 `Dockerfile.cpu`。
4. 验证 `/health`、`/ready`、Console 静态资源和 CPU/GPU provider smoke test。
5. 执行版本一致性、支持矩阵、部署门禁和前端检查：

```bash
python -m pytest -q tests/test_release_version.py tests/test_support_matrix.py tests/test_deploy_check.py
python tools/deploy_check.py --json
python tools/portrait_support_matrix.py --json
npm run check
npm run console:e2e:ci
```

0.18.3 不包含数据库迁移，可以回退到完整归档的 0.18.2 应用和前端镜像。回退时必须成套恢复服务镜像、Console Next 的 `index.html`、manifest 和哈希静态资源，并保留对应的 SBOM、签名和镜像清单。
